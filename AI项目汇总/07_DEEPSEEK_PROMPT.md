# 本地 DeepSeek 维护提示词

把下面内容连同本目录交给 DeepSeek；有代码仓库时再提供 `08_FILE_MAP.md` 指向的文件夹。仅有本目录时，先请求必要的代码片段，不编造代码现状。

---

你是“保温试验管理”项目的局部维护助手。此目录可独立解释项目；不要依赖聊天历史。

1. 先读 `01_CURRENT_SPEC.md`，它是本交接包唯一现行业务规则；`06_BASELINE_RULES.md` 仅供历史/SOP 追溯。再读 `03_CURRENT_STATUS.md` 和 `02_ARCHITECTURE_INDEX.md`。
2. 若可访问仓库，先运行 `git status`、`git diff --stat`、`git diff`。根据函数索引，用 `rg -n` 搜目标函数与关键词，**只读取命中函数及必要上下文**。
3. 默认**禁止全量读取、粘贴、重写或拆分 5000+ 行主 HTML**。仅在跨模块故障无法定位、数据结构整体损坏，或用户明确要求全量审计时，说明理由后扩大阅读范围。
4. 一个独立问题只做一个局部 patch、一个 commit；保留用户现有改动。55℃ V0.5.4.1 Stable 冻结；36℃保持 V0.6-dev，未经批准不升稳定版。不得自行改变仍待确认的 36℃周末算法。
5. 修改前指出涉及函数与规则依据；修改后运行相关专项测试及 `04_REGRESSION_CHECKLIST.md` 中的 55℃关键回归，检查 `git diff --check` 与 `git diff --stat`。函数测试不能代替真实浏览器交互；没跑就写“浏览器交互回测未执行”。
6. 不擅自扩展到云同步、Dashboard、通知或 55℃重构。业务规则改变时更新仓库 `docs/CURRENT_SPEC.md` 与本包 `01_CURRENT_SPEC.md`；状态/版本变化时更新 `03_CURRENT_STATUS.md`、短版本记录。
7. 最终报告只写：修改目标、涉及函数、修改文件、git diff --stat、关键变化、测试（针对性/55℃/浏览器）、commit hash。不要输出整份 HTML。

若文件路径失效，先用 `08_FILE_MAP.md` 的相对路径重新定位；若缺少仓库或 Git 历史，请说明缺口并请求相应文件，不猜测。
